# Critic: west_coast_night (nfl_spread, sha 3435bb84fd7c)

**6. Mechanism/Source — FAIL.** ROI 21.5% on 107 closing-line bets breaches this lab's
own bar ("ROI above 15% on 100+ bets at closing lines is a leak until shown otherwise").
Worse: `lab/registry/strategies.jsonl` S033 ("NFL travel and jet-lag spread edge (likely
refuted)", added 2026-10-06 -- *before* this strategy was logged 2026-10-09) already
covers this exact claim lineage: Borghesi-era westward/circadian studies on 1970s-2011
NFL data (the same data era SOURCE's AASM/SLEEP 2013 press release summarizes) were
re-run with a causal-inference design (medRxiv 2023 / AJE 2025) and found "compatible
with the null hypothesis," explicitly rejecting prior profitable jet-lag betting claims.
`SOURCE` in the strategy file doesn't cite S033, but should have -- it's the same
mechanism, same underlying data lineage, and a more rigorous replication already in this
project's own registry contradicts it. S033's `skeptic_note` applies directly here.

**3. Price realism — FAIL.** `sports/nfl.py` documents `spread_line`/odds as *closing*
lines. The night-kickoff + Pacific-matchup signal is knowable the moment the schedule and
opening lines post (weeks/months ahead), not at close. Backtesting at the closing price
assumes the bettor can get a public, well-known angle filled at the number right before
kickoff -- the same decay dynamic this lab already found for S031/`bye_fade` (-7.7%,
market already knows). No evidence offered that the edge survives at the opening line.

**4. Sample — thin, not disqualifying.** 107 bets, 11/14 dev seasons qualify (2006-08:
zero). folds_positive 8/11, but driven by two strong seasons (2013 +5.31u, 2016 +5.62u)
against one large loser (2015 -2.84u); ~10 bets/fold on average.

**1/2. Lookahead/Timing — PASS.** `leakcheck` PASS (folds 2009/2014/2019). `bet()` is a
pure per-row predicate on `start_utc`/`home`/`away`/`selection` (schedule facts set far
ahead of kickoff); no slate aggregates, no carried state. `fit()` returns `None`.

**5. Tuning on dev — soft concern.** Only one ledger row for this hypothesis, but the
team-code set (handles SD->LAC, OAK->LV relocations) and the 8pm-ET cutoff are real
degrees of freedom; the ledger can't show whether other cutoffs were tried locally
before this version was logged.

## Verdict: DO-NOT-PROMOTE

The mechanism is directly contradicted by a more rigorous, already-catalogued
replication (S033) covering the same claim, the backtest crosses this lab's own
closing-line leak threshold, and the price realism assumption (capturing the closing
number on a publicly known angle) is unsupported. This isn't a parameter fix -- the
registry conflict needs resolving (or a materially different mechanism argued) before
any further trial on this idea is worth spending.
