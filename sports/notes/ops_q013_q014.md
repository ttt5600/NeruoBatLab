## Learnings
### A source that moves its API gives no price signal -- watch the plumbing, not only the definition
Roll Call's 404 (2026-11-18) changed nothing about the count (952/952 same ids; 61/61 settlements fit), so no market moved,
but Q014 lost 6 decision slots (9 counting Mac-sleep gaps). source_shift_watch needs per-source endpoint health + an
exact daily rebuild vs settlement to catch this class (IDEA_PATTERNS P-8).
### A health regex must match the job's own error format
ERR_RE matched "Error"/"Traceback" but Q014 logs `"errors": ["rollcall: ... 404"]`; 211 error blocks went unflagged for
3 days. With `"errors": \["` in err_re the replay flags BROKEN after ~5.6 h, transient 504s stay WARN.
### Exact-count checks must compare brackets, not parse the expiration string
Kalshi's expiration_value can be "<5", " <5", "40+", "60-79", ">240" or "Yes". A float() parse that skips failures turns
them into silent passes (forward review 11-19). Check the rebuilt count against each market's strike bracket and result.
### Point-in-time deletion: today's deleted_flag undercounts past settlements
4/41 exact misses were posts deleted after the close (deleted_date next day 02:00-03:00 ET); counting them gives 41/41.
### Event-driven loggers need event-aware health rules
Q013's slots are close-24h/close-6h, all KXRT closes Mon 07:00 PT -> picks only Sun/Mon. A calendar zero-days rule
(3 days) fired BROKEN on a correct idle week; weekdays [6, 0] + zero_days 2 fits the schedule.
